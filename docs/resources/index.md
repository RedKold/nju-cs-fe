## ⚠️ 先读这条

**不要把大文件提交进 git。** 仓库只放文字和链接，文件本身走外部通道。

原因是硬限制：GitHub 单个文件超过 **100 MB 会被直接拒绝推送**，
仓库体积建议控制在 1 GB 以内。而且一旦提交，历史里会永久保留，
以后想删掉就得重写历史。

推荐的存放方式，按优先级：

| 方式 | 适合 | 优点 | 缺点 |
| --- | --- | --- | --- |
| **南大 Box**（[box.nju.edu.cn](https://box.nju.edu.cn)） | 课件、真题、大文件 | 校内账号直接登录，速度快，不需要提取码 | 毕业离校后账号会失效，需提前转移 |
| 网盘（百度 / 夸克 / 阿里云盘） | 课件、扫描件、录屏 | 容量大、免费 | 会失效、需要提取码、下载慢 |
| GitHub Releases | 单个较大的压缩包 | 不占仓库体积、直链稳定 | 单文件上限 2 GB |
| 仓库内直接放 | 小体积的 Markdown、代码、PDF 讲义 | 可直接版本管理 | 只适合小文件 |

校内同学优先用 **南大 Box**：不需要提取码，外网访问也稳定。
但要留意毕业后账号会失效，重要资料建议同时留一份到其他通道。

## 链接表怎么维护

每一条资料都要写清楚六件事，缺一项下一届就得重新问一遍：

```text
资料名称 | 资料类型 | 年份 | 下载链接 | 提取码 | 最后核验日期
```

**最后核验日期**是最容易被忽略但最重要的字段。网盘链接会失效，
标注核验日期能让使用者知道这条信息有多可信。

## 链接失效了怎么办

先在本仓库提一个 Issue 或 PR，把失效的那一行标注出来，
有能力的话补充一个新的可用链接。**不要直接删掉失效条目**——
有时发资料的学长学姐还在群里，可以重新分享。

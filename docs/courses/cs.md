# 计算机

这条线是工具，也是"计算机金融"里计算机两个字的分量所在。
面试和申请时最容易被追问技术深度，靠的就是这里的积累。

> ⚠️ 课程清单待按培养方案核对。

## 课程清单

| 课程 | 学期 | 前置 | 难度 | 说明 |
| --- | --- | --- | --- | --- |
| 程序设计基础 | 大一 | 无 | 中 | 选一门主力语言（C++ 或 Python） |
| 数据结构 | 大一大二 | 程序设计 | 中高 | 最影响后续一切的一门课 |
| 算法设计与分析 | 大二 | 数据结构 | 高 | 面试高频 |
| 计算机组成原理 | 大二 | 程序设计 | 中高 | 理解程序怎么在硬件上跑 |
| 操作系统 | 大二大三 | 组成原理 | 高 | 并发、内存、文件系统 |
| 计算机网络 | 大三 | 操作系统 | 中 | HTTP、TCP，排查问题必备 |
| 数据库系统 | 大三 | 数据结构 | 中 | SQL 与索引 |
| 机器学习 | 大三 | 概率统计、线代 | 中高 | 与金融结合最紧密 |

## 学习重点

**数据结构与算法** 是投入产出比最高的一门课。它同时服务三件事：
后续所有系统课的底子、推免面试的机试、就业笔试。

**操作系统** 不要只背概念。进程与线程的区别、锁与死锁、虚拟内存、
调度算法，这些在面试里会被追问到细节。

**计算机网络** 的重点是能把"输入网址到页面出现"的完整链路讲清楚，
以及 TCP 与 HTTP 的关键机制。

**机器学习** 要和金融场景结合着学。同样的模型用在价格预测、风控、
因子挖掘上，关注点完全不同。

## 考核方式（常见形态）

- 多数课程有编程作业或实验，占分不低
- 部分课程设机试，形式接近在线判题
- 理论课期末以概念题和设计题为主

## 学习建议

1. **代码量要够。** 看懂和写出来之间差着一整个数量级，作业自己写。
2. **刷题早开始。** 大三再突击算法题会很痛苦，大二下开始每周几道即可。
3. **做一两个完整项目。** 小游戏、爬虫、数据可视化都行，重点是"完整"——
   从需求到能跑起来，而不是半途而废的 demo。
4. **把项目和课程对应起来。** 简历上写"用 A 算法解决了 B 问题"比罗列技能列表有说服力。
